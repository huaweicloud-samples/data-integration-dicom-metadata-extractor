# 架构设计文档

## 1. 设计目标

构建一个高可用、低成本、自动化的医疗影像元数据提取与查询平台，满足以下需求:

- DICOM 文件上传后自动触发元数据提取
- 支持小文件实时处理与大文件批量处理
- 元数据结构化存储，支持 SQL 查询
- 处理失败自动告警
- 全资源通过 Terraform 管理，一键部署

## 3. 组件设计

### 3.1 OBS 对象存储 (输入桶)

**职责**: 接收 DICOM 文件上传，触发后续处理流程。

**设计要点**:
- 桶权限: 私有，仅授权用户可写
- 事件通知: 配置 ObjectCreated 事件，触发 FunctionGraph
- 生命周期: 可配置过期策略，定期清理已处理文件
- 加密: 可选 SSE-KMS 加密

**触发机制**:
OBS 事件通知在对象创建后异步触发 FunctionGraph 函数。触发器配置为监听 `ObjectCreated` 事件，支持 PUT/POST/CompleteMultipartUpload 等上传方式。

### 3.2 FunctionGraph 无服务器函数

**职责**: 下载 DICOM 文件，解析元数据，写入 DLI，归档结果。

**处理流程**:
```
+----------+     +----------+     +----------+     +----------+
| 接收触发 |---->| 下载文件 |---->| 解析 DICOM|---->| 判断大小 |
|  事件    |     | 从 OBS   |     | 元数据    |     | 路由     |
+----------+     +----------+     +----------+     +----------+
                                                        |
                                          +-------------+-------------+
                                          |                           |
                                     小文件                        大文件
                                          |                           |
                                          v                           v
                                   +----------+              +----------+
                                   | 写入 DLI |              | 提交 CCE |
                                   | 表       |              | 批处理   |
                                   +----------+              +----------+
                                          |                           |
                                          v                           v
                                   +----------+              +----------+
                                   | 归档到   |              | 归档到   |
                                   | 输出桶   |              | 输出桶   |
                                   +----------+              +----------+
```

**配置参数**:
- 内存: 512MB (默认)，可按需调整
- 超时: 300秒 (默认)，大文件场景建议增大
- 并发: 由 FunctionGraph 自动管理
- 运行时: Python 3.9

### 3.3 CCE 云容器引擎 (批处理)

**职责**: 处理大文件或批量历史数据的元数据提取。

**设计要点**:
- 集群类型: 按需弹性集群，空闲时不产生计算费用
- 节点规格: 通用计算型，根据文件大小选择
- 容器镜像: 通过 Dockerfile 构建，包含 pydicom 等依赖
- 任务模式: Kubernetes Job，处理完成后自动释放

**大文件路由逻辑**:
当 DICOM 文件大小超过 `max_file_size_mb` 阈值时，函数不直接处理，而是将文件信息提交到 CCE 批处理队列。CCE Job 从 OBS 拉取文件，在容器中完成解析后写入 DLI。

### 3.4 DLI 数据湖探索

**职责**: 存储结构化元数据，提供 SQL 查询能力。

**表结构设计**:
```
+-------------------+-----------+--------------------------------+
| 字段名            | 类型      | 说明                           |
+-------------------+-----------+--------------------------------+
| patient_id        | STRING    | 患者ID                         |
| patient_name      | STRING    | 患者姓名                       |
| study_date        | STRING    | 检查日期                       |
| modality          | STRING    | 模态 (CT/MR/US等)             |
| study_description | STRING    | 检查描述                       |
| series_description| STRING    | 序列描述                       |
| institution_name  | STRING    | 机构名称                       |
| manufacturer      | STRING    | 设备厂商                       |
| file_path         | STRING    | OBS 文件路径                   |
| file_size         | BIGINT    | 文件大小 (字节)               |
| process_time      | TIMESTAMP | 处理时间                       |
| status            | STRING    | 处理状态                       |
+-------------------+-----------+--------------------------------+
```

### 3.5 SMN 消息通知

**职责**: 处理失败时推送告警通知。

**通知内容**:
- 失败文件路径
- 错误类型与错误信息
- 触发时间
- 函数执行 ID

**订阅方式**: 邮件、短信、HTTP/Webhook

### 3.6 IAM 委托

**职责**: 授予 FunctionGraph 函数访问其他云服务的权限。

**权限范围** (最小权限原则):
- OBS: 指定桶的读写权限
- DLI: 指定数据库的写入权限
- CCE: 指定集群的 Job 创建权限
- SMN: 指定主题的发布权限

## 4. 数据流详解

### 4.1 正常处理流程

```
用户上传 DICOM 文件
        |
        v
OBS 输入桶接收对象
        |
        v (ObjectCreated 事件)
FunctionGraph 函数触发
        |
        v
函数通过 IAM 委托下载文件
        |
        v
pydicom 解析 DICOM 标签
        |
        v
判断文件大小
    |           |
    v           v
(< 阈值)    (>= 阈值)
    |           |
    v           v
写入 DLI 表   提交 CCE Job
    |           |
    v           v
归档到输出桶  CCE 下载并解析
                |
                v
            写入 DLI 表
                |
                v
            归档到输出桶
```

### 4.2 异常处理流程

```
处理过程中发生异常
        |
        v
捕获异常，记录错误日志
        |
        v
发送 SMN 错误通知
        |
        v
函数返回错误状态
        |
        v
原始文件保留在输入桶
(不删除，等待人工处理)
```

## 5. 高可用设计

- **FunctionGraph**: 原生多可用区部署，自动故障转移
- **OBS**: 数据三副本存储，可用性 99.99%
- **CCE**: 多节点部署，Pod 自动重启
- **DLI**: 托管服务，自动维护高可用

## 6. 安全设计

- **网络隔离**: CCE 节点位于私有子网，通过 NAT 网关出公网
- **传输加密**: 全链路 HTTPS/TLS
- **存储加密**: OBS 可选 SSE-KMS
- **访问控制**: IAM 委托最小权限，安全组严格限制
- **审计日志**: OBS 访问日志 + FunctionGraph 执行日志

## 7. 扩展性设计

- **水平扩展**: FunctionGraph 自动扩缩容，CCE 支持弹性伸缩
- **数据扩展**: DLI 表支持动态分区，OBS 无限容量
- **功能扩展**: 函数代码模块化设计，易于添加新处理逻辑
- **区域扩展**: Terraform 模板化，支持多区域部署
